Slide 1 — Introduction to IoT Security

هذه الشريحة عنوان المحاضرة، وما فيها تعريفات للحفظ.

IoT Security يعني أمن إنترنت الأشياء، والمقصود دراسة الجوانب الأمنية للأجهزة الذكية المتصلة والخدمات اللي بتعتمد عليها.

الرسم بيوضح مكونات النظام بشكل تسلسلي للتعلّم، لكن مش شرط كل جهاز يمر عبر Gateway أو يتبع نفس المسار.

شرح المكونات واحد واحد

1. Physical Device — الجهاز الفيزيائي

هو الجهاز الموجود فعليًا في البيئة.

يتكوّن من:

  • Sensors: حساسات بتجمع معلومات من البيئة.

  • Actuators: أجزاء بتنفّذ أفعال فيزيائية.

  • Processor: معالج بنفّذ العمليات والتعليمات.

مثال: في Smart Lock، ممكن يكون في حساس لحالة الباب وآلية قفل بتنفذ أوامر الفتح والإغلاق.

2. Device Software — برمجيات الجهاز

هي البرامج اللي بتحدد كيف الجهاز يبدأ التشغيل، وكيف يتصرف، وكيف يخزّن إعداداته ويتواصل.

Boot: عملية بدء تشغيل الجهاز.

Configuration: إعدادات الجهاز.

Application: البرنامج اللي بينفذ وظائف الجهاز.

3. Connectivity — الاتصال

هي الطرق اللي الجهاز بستخدمها للتواصل مع المكونات الأخرى، سواء محليًا أو عبر الإنترنت.

مهم: الاتصال مش محصور بالـWi-Fi.

4. Gateway / Edge — البوابة أو الطبقة الوسيطة

هي مكوّن ممكن يربط أجهزة محلية بشبكات أو خدمات أخرى.

ممكن يقوم بتجميع البيانات، أو تحويل طريقة الاتصال، أو المعالجة المحلية.

مثال: عدة حساسات داخل مبنى ترسل بياناتها إلى Gateway واحد، وهو بدوره يرسلها للخدمة البعيدة.

5. Cloud Service — الخدمة السحابية

هي الخدمات البعيدة اللي ممكن تخزّن بيانات الأجهزة، وتدير الحسابات، وتسجل الأجهزة، وترسل الأوامر.

مثال: خدمة تخزين تسجيلات كاميرا ذكية.

6. User Application — تطبيق المستخدم

هو واجهة التفاعل بين الإنسان والنظام، مثل تطبيق الهاتف أو صفحة الويب.

من خلاله ممكن المستخدم يشاهد المعلومات أو يرسل أوامر.

Slide 4 — Opening Scenario: A Smart Camera Is More Than a Camera

A smart camera is more than its lens and processor. Access to recordings may involve an account, network, service, and application. Separate working hardware from end-to-end service availability.

The camera may still record locally while its app cannot retrieve remote recordings because the cloud service is unavailable.

Understand the Components

  • Hardware: camera, processor, memory.
  • Software: the program operating the camera.
  • Network: communication with other parts.
  • Cloud Service: remote storage or account management.
  • Mobile Application: viewing and control.

Where Could a Security Issue Arise?

  • Weak Account: inappropriate access through weak account protection.
  • Exposed Cloud Service: unintended access to a remote service.
  • Unsafe Installation: insecure installation or settings.
  • Compromised Device: loss of the intended trusted state.

Where does the security boundary of the camera actually end? It extends beyond its physical enclosure to relevant networks, cloud services, applications, and users.

Slide 5 — A Modern Connected-Device Ecosystem

An IoT ecosystem is the collection of interacting parts that deliver a connected function. The device is a starting point; the result may also rely on software, networking, gateways, services, applications, and users.

A temperature sensor measures a room. Software prepares the reading, connectivity transports it, a gateway may aggregate it, a service stores it, and an app displays it.

This sequence is a teaching model. Not every device requires a gateway or follows the same route.

1. Physical Device

This is the physical equipment that interacts with its environment. Sensors collect measurements, actuators perform actions, and a processor executes instructions. It differs from software and remote services.

Example: A smart lock contains a door-state sensor, a locking mechanism, and a processor coordinating its operation.

  • Sensors collect information.
  • Actuators perform physical actions.
  • A processor executes instructions.

2. Device Software

Device software determines startup, behavior, configuration, and communication. Identical hardware may behave differently when software or settings change.

Example: A thermostat starts up, loads settings, processes measurements, and communicates results.

  • Boot: starting the device.
  • Configuration: device settings.
  • Application: the program performing device functions.

3. Connectivity

Connectivity is the communication between components. It may be local, internet-based, or gateway-mediated; it is not limited to Wi-Fi.

Example: A building sensor may send readings to a gateway while another device connects directly to a service.

4. Gateway / Edge

A gateway can bridge local devices to other networks or services, aggregate data, or adapt communication. Edge refers to processing near the devices. The roles may overlap but are not identical.

Example: Several sensors send readings to one local component before forwarding them to a remote service.

5. Cloud Service

A cloud service is remote infrastructure that may store data, manage accounts and devices, or deliver commands. Losing cloud connectivity does not necessarily stop every local device function; that depends on design.

Example: Remote recordings may become unavailable in the app during a cloud outage even if local recording continues.

6. User Application

The user application is the human-facing interface, such as a mobile app or website. Viewing information, issuing commands, and managing access make user interaction part of system analysis.

Example: You open a lock app, view door status, and request unlocking; the app is not the actuator moving the lock.
